# 新人准备工作手册（PICO VR 游戏开发）

> **给谁看**：完全没碰过 Unity、没做过 VR、也不写代码的同学。
> **这份文档解决什么**：从一台干净的电脑，到"能开始做游戏"的全部准备工作。
> **预计耗时**：1.5 小时左右，其中大部分是下载等待。
> **不需要**：不需要学 Unity 界面，不需要学编程，不需要买头显。
>
> 本手册有配套的培训 PPT（18 页，讲解用）：[`docs/training/PICO-VR新人培训.pptx`](training/PICO-VR新人培训.pptx)。内容以本文档为准，PPT 用于开场宣讲。

---

## 0. 先理解你要扮演什么角色

这套做法的分工是：

> **你负责判断"这是不是我想要的"，AI 负责所有动手的部分。**

你不写代码，也不操作 Unity。你会做的就是：说清楚要什么 → 看 AI 给的截图 → 说哪里不对。

所以准备工作的目标只有一个：**让你的电脑能跑通"改代码 → 打包 → 装进模拟器 → 看到画面"这一整圈**。跑通了，你就能开始做游戏了。

## 1. 硬件与环境门槛（先自查，别白装）

**Windows 和 macOS 都支持**，这是 PICO 官方明确写的要求（PICO Emulator 文档 · System requirements）：

| 平台 | 系统 | 内存 | 硬盘 | CPU / 显卡 |
|---|---|---|---|---|
| **macOS** | 14.0 及以上 | 16GB+ | 40GB+ | 芯片至少 **M1 Pro**（普通 M1 / M2 基础版**不达标**） |
| **Windows** | Windows 10 64 位及以上 | 16GB+ | 40GB+ | CPU 至少 **Intel Core i5**；**显卡至少 NVIDIA GTX 1060** |

另外两个所有平台都要满足的门槛：

| 项目 | 要求 | 不满足会怎样 |
|---|---|---|
| 网络 | 能访问 GitHub | 拉不了 PICO SDK，打包必失败 |
| Intel Mac | **不支持** | 模拟器起不来，这条路堵死 |

> **Windows 同事注意**：真正的硬门槛是**独立显卡**。只有集显的轻薄本、或者显卡低于 GTX 1060 的机器，模拟器会起不来或卡到不可用。开工前先确认自己的显卡型号。
>
> **Mac 同事注意**：不是"苹果芯片就行"，官方要求 **M1 Pro 及以上**。M1 / M2 基础款属于擦边，若不达标会表现为模拟器极慢或启动失败。

> 数据来源：PICO 官方文档《PICO Emulator》→ System requirements（2026-10 核对）。官方还提供另一条安装路径（Android Studio + PICO Spatial 插件），如果你的电脑上已经有 Android Studio 也可以走那条；本手册用 `pico-cli`，步骤更少。

## 2. 软件安装清单（严格按顺序）

总共 6 样东西。**每一步都有"成功标志"，对不上就别往下走。**

### 步骤 1｜装 Git LFS ★ 最容易漏，漏了后面必卡

**macOS：**

```bash
brew install git-lfs
git lfs install
```

> 没有 Homebrew 的话，先让 AI 装：`帮我安装 Homebrew`

**Windows（二选一）：**

```powershell
winget install GitHub.GitLFS
git lfs install
```

或者去 https://git-lfs.com 下载安装包，装完后开一个新终端执行 `git lfs install`。

**成功标志**：`git lfs version` 有版本号输出，且执行过 `git lfs install`（会输出 `Git LFS initialized.`）。

> **为什么这一步这么重要**：PICO 的 SDK 用 Git LFS 存大文件。没装它，SDK 下载会静默失败，你看到的只是"Unity 卡住了"，非常难查。**这是我们实际踩过的坑。**

---

### 步骤 2｜装 Node.js（20 以上）

**macOS：** `brew install node`

**Windows：** 去 https://nodejs.org 下 LTS 安装包，或 `winget install OpenJS.NodeJS.LTS`

**成功标志**：终端输入 `node -v`，输出 `v20.x` 或更高（v22 也可以）。

---

### 步骤 3｜（只有 Windows 需要）开启虚拟化

Windows 上的模拟器依赖 Hyper-V 跑虚拟机，**不开会起不来**。

1. 重启进入 **BIOS/UEFI**，打开 CPU 虚拟化（Intel 叫 **VT-x**，AMD 叫 **AMD-V**）
2. 回到系统，**以管理员身份**打开 PowerShell，执行：

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
bcdedit /set hypervisorlaunchtype auto
```

3. **重启电脑**（不重启不生效，这是最常见的"我明明开了还是不行"）

**成功标志**：重启后执行 `pico-cli emulator doctor`，虚拟化相关的检查不再报错；或者任务管理器 → 性能 → CPU 里能看到"虚拟化：已启用"。

> Mac 用户跳过这一步，macOS 自带虚拟化框架。

---

### 步骤 4｜装 Unity Hub + Unity 编辑器 ★ 耗时最长

1. 去 Unity 官网下 **Unity Hub**（⚠️ 国内访问官网可能被跳到"团结引擎"，要装**国际版**，别装团结引擎）
2. 打开 Hub → 左侧 **Installs** → **Install Editor** → 选 **Unity 6000.x**（6000 系列任意版本都行，团队统一用一个）
3. 安装时**必须勾选**：
   - ☑️ **Android Build Support**
     - ☑️ Android SDK & NDK Tools
     - ☑️ OpenJDK
   - ☑️ **本机平台的 Build Support**（Mac 用户勾 `Mac Build Support`，Windows 用户勾 `Windows Build Support`）

**成功标志**：
- Hub 的 Installs 列表里能看到这个版本
- 点开它的详情，能看到 Android 相关模块已勾选

> **为什么必须装 Android 模块**：PICO 头显跑的是安卓系统，没有这个模块，你的游戏打包不出来。漏装的表现是打包时报"build target not supported"。

---

### 步骤 5｜装 PICO CLI（官方 AI 开发入口）

```bash
npm install -g @picoxr/pico-cli
pico-cli --version
```

**成功标志**：输出类似 `pico-cli/0.6.1`。

---

### 步骤 6｜跑一次环境配置

```bash
pico-cli setup
```

按提示选：
- **AI 助手**：选你实际在用的那个（Claude Code / Codex / Cursor / TRAE / OpenCode 等）
- **平台**：选 **Unity**
- **区域**：中国选 `cn`

**成功标志**：最后提示配置完成，没有 Error。

> 如果报错说某个旧配置文件格式不对（比如 OpenCode 的旧版 MCP 配置），按提示把它改名备份掉即可，别直接删。

---

## 3. 验证环境（这一步做完才叫"准备就绪"）

### 3.1 体检

```bash
pico-cli doctor
```

**你要看的**：
- `Runtime: ok`
- `Emulator doctor: PICO Emulator prerequisites are ready`
- `PICO environment setup: PICO environment is set up`
- `Android SDK: ... available`

出现黄色 `warn` 通常不影响，可以继续；出现红色 `error` 就丢给 AI。

> **Windows 用户额外看一条**：如果出现 "Windows virtualization prerequisites are not fully ready"，说明虚拟化没开好，回到步骤 3 检查并**重启电脑**。这条不解决，模拟器一定起不来。

### 3.2 启动模拟器

```bash
pico-cli emulator start
pico-cli device list
```

**成功标志**：
- 弹出一个 VR 房间窗口（床、台灯、书架）
- `device list` 输出里有 `emulator-5554  device`

### 3.3 用鼠标键盘试一下

模拟器窗口里，**鼠标 + 键盘可以走动和转头**。

**成功标志**：转动视角，画面跟着动。

> 这一步很重要——先确认"我能不能在这个虚拟房间里自由活动"，再去碰游戏。不然之后分不清是环境问题还是游戏问题。

### 3.4 装一个健康检查截图

让 AI 截一张模拟器画面给你：

```
截一张模拟器的图给我看看
```

**成功标志**：你收到一张 VR 房间的图片。这说明"AI 能自己看到画面"——**这是后续所有验收方式的基础**，以后不用你人肉盯着 Unity 了。

---

## 4. 拿到项目，跑通第一圈

准备工作最后一步：把要做的游戏工程跑起来。

### 4.1 拿到工程
向负责人要项目目录（一个叫 `PicoHammerDemo` 的文件夹），放到你觉得合适的位置（建议 `~/Developer/`）。

### 4.2 第一次跑通

把下面这段**整段复制给 AI**：

```
项目在 <你的路径>/PicoHammerDemo。

请帮我：
1. 打开这个 Unity 项目（构建目标设为 Android）
2. 打包成 APK
3. 装进 PICO 模拟器并启动
4. 截图给我看

如果中间报错，先查日志定位原因，不要猜。
```

**成功标志**：你收到一张游戏画面截图，里面有场景里的物体。

> 第一次打包会比较慢（8 分钟左右），之后每次改动只要 1～2 分钟。

## 5. 准备阶段的常见卡点

| 现象 | 大概率原因 | 怎么处理 |
|---|---|---|
| 一直卡在"下载 SDK" / 打包卡死 | 没装 Git LFS（步骤 1） | 装上后删掉工程里 `Library/PackageCache/com.bytedance.*`，重开 Unity |
| 打包报 `build target not supported` | Unity 没装 Android 模块 | 回 Unity Hub 补装 Android Build Support |
| 模拟器起不来 / 报 device not found | 模拟器没启动成功，或上一次残留 | 重新 `pico-cli emulator start` |
| **（Windows）模拟器报硬件加速失败 / 提示虚拟化未就绪** | Hyper-V 没开、或开了没重启、或 BIOS 里 CPU 虚拟化没开 | 回步骤 3，改完**必须重启**；显卡低于 GTX 1060 的机器无解 |
| **（Mac）模拟器极慢或启动失败** | 芯片是 M1/M2 基础款，未达官方要求的 M1 Pro | 换机器，或改用真机调试 |
| 从 GitHub 拉代码失败 | 网络问题 / 没配 SSH | 让 AI 改用 HTTPS 源，或配 SSH |
| `pico-cli setup` 报配置文件冲突 | 本机有旧版 AI 配置 | 按提示把旧文件**改名备份**，不要删 |
| 装完 Unity 还是打不开项目 | Unity 版本比项目要求的低 | 用项目指定的 Unity 6000.x 版本 |
| 打包报 `PXR SDK validation failed` | 安卓启动方式不合规 | 交给 AI 修，一个开关的事 |

**共性**：以上没有一个是"你操作错了"，都是环境问题。**所以不要自己去 Unity 界面里乱点乱试**，把现象描述给 AI 更快。

## 6. 准备完成检查清单

全部打勾，你才算"可以开始做游戏"：

- [ ] 机器达到官方门槛（Mac 是 M1 Pro+；Windows 是 i5 + GTX 1060 以上独显）
- [ ] `git lfs version` 有输出，且执行过 `git lfs install`
- [ ] `node -v` 是 20 以上
- [ ] （仅 Windows）BIOS 虚拟化已开、Hyper-V 已启用、**已重启过**
- [ ] Unity Hub 里装了 Unity 6000.x，**且带 Android Build Support**
- [ ] `pico-cli --version` 有版本号
- [ ] `pico-cli doctor` 没有红色 error
- [ ] `pico-cli device list` 能看到 `emulator-5554`
- [ ] 模拟器窗口能打开，鼠标键盘能转头走动
- [ ] AI 能自己截一张模拟器画面给你
- [ ] 项目能打包、装进模拟器、启动、出画面

**全部打勾 = 准备完毕。**

## 7. 准备阶段会听到的黑话（最小集）

| 他们说的 | 实际意思 |
|---|---|
| Unity | 做 3D/VR 内容用的软件 |
| Unity Hub | 管理 Unity 版本的工具（先装它，再装 Unity） |
| Android Build Support | 让 Unity 能打包成安卓应用的模块，**必须装** |
| Build / 打包 | 把工程变成能装到头显上的安装包 |
| APK | 那个安装包的文件格式 |
| 模拟器 / Emulator | 在电脑上模拟头显的软件，不用真机就能测 |
| SDK | 官方给的一堆现成能力包 |
| adb / device | 用来连接和操作模拟器/真机的工具，`emulator-5554` 就是模拟器的编号 |
| 驱动 / Driver | 让系统能正常用某个硬件或软件的组件 |

## 8. 给 AI 的开场白（第一次会话直接复制）

```
我是第一次接触 Unity 和 VR 开发，不写代码。
项目在 <路径>/PicoHammerDemo。

请先读项目里的 docs/DEVLOG.md 了解现状，
然后告诉我：现在做到哪一步了、下一步该做什么。
过程中你负责所有动手的操作，包括打包、装模拟器、截图。
需要我判断的地方，用截图问我。
```

---

## 9. 三件千万不要做的事

1. **不要自己去 Unity 界面里点。**
   状态很容易改乱，AI 之后要花更多时间排查。要改什么，说出来。

2. **不要接受"应该可以了"。**
   没有截图就是没验证。坚持要它截图。

3. **不要一开始就纠结美术。**
   先用方块球体把玩法跑通，模型永远可以后补。
